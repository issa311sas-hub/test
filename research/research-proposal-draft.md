## 1. 研究題目（仮）

**「LLM はハルシネーションを自己検知できるか —— Verbalized Confidence によるハルシネーション検出の実証的評価」**

### 副題案
- 「大規模言語モデルは自分が間違っていることを知れるのか」
- 「否定的内省公理の実証テスト：LLM の "知らないことを知る" 能力」
- 「Verbalized Confidence を用いたハルシネーション自己検出器の性能評価」

---

## 2. 研究の背景と動機

### 2.1 背景
ChatGPT をはじめとする大規模言語モデル（Large Language Models, LLM）は、2023年以降、教育・業務・日常生活に急速に浸透している。しかし、LLM は**自信満々に誤った情報を生成する（ハルシネーション, hallucination）**という根本的な問題を抱えている。ハルシネーションの対処は LLM 研究における最重要課題の一つである。

ハルシネーション対処には多くのアプローチが提案されているが、本研究では**最も直接的な問い**に焦点を当てる：**LLM は自分がハルシネーションしていることを自ら検知できるのか？** もし LLM が「この回答は間違っているかもしれない」と正しく認識できるなら、それ自体が最もシンプルなハルシネーション回避メカニズムとなる。

### 2.2 問題意識
先行研究（Kadavath et al. 2022; Tian et al. 2023; Xiong et al. 2024）は LLM に確信度を表明させる（verbalized confidence）手法を提案し、その calibration を測定してきた。しかし、これらの研究は「信頼度のズレがどれだけあるか」という記述的分析にとどまっており、以下のより直接的な問いに答えていない：

- verbalized confidence はハルシネーション**検出器**として実用的に機能するか？
- 「自信がない」と言った場合、実際にどれだけの精度で誤答を検出できるか？
- 閾値の設定次第で、どの程度のハルシネーション回避が可能か？
- LLM に回答を「棄却」させることで、残った回答の信頼性はどこまで上がるか？

さらに、これらの検証は英語中心に行われており、日本語での実証は空白である。

### 2.3 本研究の動機
本研究は、LLM の verbalized confidence を**ハルシネーション自己検出器**として評価する。単に calibration を記述するのではなく、「この検出器はどれだけ使えるか？」「どう使えば最も効果的か？」という処方的（prescriptive）な問いに答える。

意義：
1. **学術的貢献**: calibration 研究を「記述」から「ハルシネーション検出性能の評価」へ前進させる
2. **実用的貢献**: ユーザーや開発者に「confidence が X 以下なら棄却」という具体的な運用指針を提供
3. **理論的貢献**: DEL の否定的内省公理（¬Kφ → K¬Kφ）の実証テストとして位置づける

### 2.4 理論的フレーミング: 否定的内省公理の実証テスト

本研究は指導教員のご専門である **動的認識論理（Dynamic Epistemic Logic, DEL）**
の中核概念と直接対応する。

DEL における **否定的内省公理**:
```
¬K_a φ → K_a ¬K_a φ
（エージェント a が φ を知らないならば、a は自分が知らないことを知っている）
```

**本研究との対応**:
- φ = 「この回答は正しい」
- ¬K_a φ = ハルシネーション（LLM は正解を知らない）
- K_a ¬K_a φ = LLM が「自分は間違っているかもしれない」と正しく認識する
- **本研究の問い = この公理は LLM で経験的に成り立つか？**

| DEL 概念 | 本研究での直接テスト | 主指標 |
|---|---|---|
| `¬K φ → K ¬K φ`（否定的内省） | 誤答時に低 confidence を出せるか | **AUROC, Recall** |
| `K φ → φ`（真理性） | 高 confidence は正答と対応するか | **Precision@threshold** |
| `B φ → B B φ`（正の内省） | confidence の安定性 | プロンプト間一貫性 |
| `[!φ]` 動的更新 | 棄却プロンプト追加後の改善 | 棄却後精度向上幅 |

v0.1 では calibration の記述的測定が主目的で DEL は「フレーミング」に過ぎなかった。
v0.2 では**否定的内省公理の実証テストそのものが研究の問い**となり、DEL は
装飾ではなく研究の理論的骨格である。

詳細は `research/advisor-theme-alignment.md` を参照。

## 3. 研究の問い（Research Questions）

### メイン RQ
**RQ0**: LLM は自身のハルシネーション（誤答）を、verbalized confidence を通じて自己検知できるか？

### サブ RQ

| # | 問い | 対応する分析 |
|---|---|---|
| **RQ1** | Verbalized confidence はハルシネーション検出器としてどの程度の精度を持つか？ | AUROC, Precision/Recall 曲線 |
| **RQ2** | 信頼度閾値によるフィルタリングは、残存回答の正答率をどこまで改善するか？ | F1@threshold, 棄却率-精度トレードオフ |
| **RQ3** | LLM に「分からない」選択肢を与えることで、ハルシネーション回避率は向上するか？ | 棄却率、棄却時の正答率向上幅 |
| **RQ4** | モデル間（商用 vs 日本語特化）でハルシネーション自己検知能力に差はあるか？ | モデル別 AUROC 比較 |
| **RQ5** | ドメイン（数学／歴史／常識／翻訳）によって自己検知能力は変化するか？ | ドメイン別 AUROC |
| **RQ6** | 確信度の引き出し方（プロンプト方式）によって検出性能は変わるか？ | プロンプト別 AUROC |

### RQ の構造（案 A + B + C の統合）
```
RQ1: 検出できるか？（案A: 基本性能評価）
RQ2: フィルタとして使えるか？（案B: 閾値戦略の実用性）
RQ3: 棄却で回避できるか？（案C: 棄却戦略の有効性）
RQ4-6: 条件による差は？（交差分析）
```

### 4.5 本研究の位置づけ
先行研究は calibration の**記述的測定**（ECE がいくつか）に焦点を当てており、

は十分に評価されていない。本研究は以下の 3 軸で新規性を持つ:

1. **問いの転換**: calibration の記述 → ハルシネーション自己検知能力の検証（処方的）
2. **DEL 理論接続**: 否定的内省公理の実証テストとして理論的に位置づける
3. **日本語実証**: 英語中心の先行研究に対し、日本語タスクでの初の体系的評価

## 5. 研究方法

### 5.1 実験の全体像
以下の3つの実験を順次行う：

| 実験 | 目的 | 扱う変数 |
|---|---|---|
| 実験1 | 基本 calibration の測定 | モデル × ドメイン |
| 実験2 | プロンプト方式の影響 | プロンプトフォーマット |
| 実験3 | 言語の影響 | 日本語 vs 英語 |

### 5.2 データセット（各ドメイン25問、合計100問 ← 原計画200問から縮減）

| ドメイン | 出典候補 | 例 |
|---|---|---|
| 数学 | JEMHopQA, 中高生向け問題集 | 文章題、計算問題 |
| 日本史 | 共通テスト過去問改変 | 事実質問 |
| 一般常識 | JCommonsenseQA | 多肢選択 |
| 翻訳 | Flores-200（日英） | 短文翻訳 |

### 5.3 使用モデル（4〜6モデル）
- **商用**: GPT-4o / GPT-5, Claude Sonnet 4.6, Gemini 2.x
- **オープン**: Swallow, ELYZA-japanese-Llama, Qwen
- モデルのバージョン・取得日時は必ず記録する

### 5.4 プロンプトフォーマット

#### 基本形（RQ1, RQ2 用）
```
以下の問題に回答してください。さらに、自分の回答が正しい
確率を0〜100の整数で表してください。

問題: {question}

出力形式:
回答: ...
信頼度: XX
```

#### 棄却許容形（RQ3 用）
```
以下の問題に回答してください。自信がない場合は「分からない」
と回答しても構いません。回答する場合は、正しい確率を
0〜100の整数で表してください。

問題: {question}

出力形式:
回答: ...（または「分からない」）
信頼度: XX（「分からない」の場合は不要）
```

### 5.5 評価指標

#### 主指標（ハルシネーション検出性能）
- **AUROC**: confidence で正誤を分離できる度合い（検出器の基本性能）
- **Precision@threshold**: 閾値以下を「ハルシネーション」と判定した場合の適合率
- **Recall@threshold**: 実際の誤答のうち何%を検出できたか
- **F1@threshold**: 最適閾値での Precision-Recall バランス
- **棄却後正答率**: confidence < θ を棄却した残りの正答率（実用性指標）

#### 補助指標（calibration の記述）
- **ECE (Expected Calibration Error)**: 信頼度と正答率のズレ（参考値として報告）
- **Brier Score**: 確率予測の精度
- **Reliability Diagram**: 視覚化

#### 追加分析
- **Precision-Recall 曲線**: 閾値を変えた時の検出性能変化
- **棄却率 vs 精度トレードオフ曲線**: 何%棄却すれば何%正答率が得られるか
- **「分からない」回答の分析**: 棄却プロンプト条件での回避成功率
- **統計検定**: モデル間の有意差（Friedman 検定など）

### 5.6 実験手順
1. 問題100問をGoogleスプレッドシートに整備（正解ラベル付き）
2. Python スクリプトで各モデルに一括問い合わせ
3. 回答と確信度をCSVに保存
4. 正誤判定を自動＋人手で確認
5. 指標を計算・可視化
6. 統計検定を行う

## 7. 予想される成果

- LLM の verbalized confidence がハルシネーション検出器としてどの程度機能するかの定量的評価
- 「confidence < θ なら棄却」戦略の実用性（最適閾値と期待正答率改善幅の提示）
- 「分からない」回答を許容するプロンプト設計がハルシネーション回避に有効かの検証
- モデル間・ドメイン間での自己検知能力の差異の可視化
- DEL 否定的内省公理の経験的充足度に関する知見（どの条件で公理が破れるか）
