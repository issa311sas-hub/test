# リスク台帳（Risk Register）

> **作成日**: 2026年4月9日
> **目的**: 卒業研究で起こりうるリスクを事前に洗い出し、対応策を準備する
> **更新頻度**: 月1回以上

---

## リスク評価の凡例

- **影響度**: 低 (1) / 中 (2) / 高 (3)
- **発生可能性**: 低 (1) / 中 (2) / 高 (3)
- **スコア**: 影響度 × 発生可能性（最大9点）
- **優先度**: 
  - 🔴 高（スコア 6〜9）: すぐ対応策を準備
  - 🟡 中（スコア 3〜5）: 発生時の対応を決めておく
  - 🟢 低（スコア 1〜2）: 監視のみ

---

## 1. テーマ・計画に関するリスク

### R-001 テーマが指導教員の専門と合わない 🔴
- **影響度**: 高 / **発生可能性**: 中 / **スコア**: 6
- **発生時の症状**: 指導教員から「このテーマは私の専門外なので指導できない」と言われる
- **予防策**:
  - 最初の面談までに指導教員の過去論文を確認
  - メールで事前に方向性を伝える
  - 複数の方向性を準備しておく
- **発生時の対応**:
  - 指導教員の専門に近いテーマへ軌道修正
  - 共同指導を依頼する選択肢を探る
- **期限**: 4月末までに確定

### R-002 テーマの新規性が主張できない 🟡
- **影響度**: 中 / **発生可能性**: 中 / **スコア**: 4
- **発生時の症状**: 文献調査で「既に同じ研究がある」ことが発覚
- **予防策**:
  - 4月中に重要先行研究5本を精読
  - 新規性の軸を複数用意（言語・モデル・タスクなど）
- **発生時の対応**:
  - 新規性の軸を変える（例: 言語から手法へ）
  - 対象モデルを最新のものに変更
  - 比較対象を追加して「比較研究」に位置づけ直す

## 2. 技術・実装に関するリスク

### R-003 API費用が想定を大幅に超える 🟡
- **影響度**: 中 / **発生可能性**: 中 / **スコア**: 4
- **発生時の症状**: 月末に請求が10,000円を超える
- **予防策**:
  - 予算上限を設定（例: 月3,000円）
  - APIキーにレート制限を設定
  - パイロットで単価を実測
- **発生時の対応**:
  - 問題数を削減
  - モデル数を削減
  - オープンモデル（ローカル実行）へ切り替え

### R-004 モデルのバージョンアップで結果が変わる 🔴
- **影響度**: 高 / **発生可能性**: 高 / **スコア**: 9
- **発生時の症状**: 実験途中でAPIモデルが更新され、結果が非整合になる
- **予防策**:
  - モデルバージョンを固定指定する（可能な場合）
  - 実行日時を必ず記録
  - 主要実験は短期間に集中して実施
- **発生時の対応**:
  - 全モデルを再実行
  - 論文内に「時期限定の知見」として明記
  - 古いモデルと新モデルの比較自体を研究の一部にする

### R-005 API のレート制限に頻繁に引っかかる 🟡
- **影響度**: 中 / **発生可能性**: 高 / **スコア**: 6
- **予防策**:
  - リクエスト間にスリープを入れる
  - バッチAPI（OpenAI）の活用を検討
  - 再試行ロジックを実装
- **発生時の対応**:
  - スリープ時間を増やす
  - 実行を分散（複数日に分けて実行）

### R-006 パース失敗率が高い（モデルがフォーマットを守らない）🟡
- **影響度**: 中 / **発生可能性**: 中 / **スコア**: 4
- **予防策**:
  - パイロット実験でパース率を測定
  - 正規表現を複数パターン用意
  - モデル別のプロンプト微調整
- **発生時の対応**:
  - 手動でのデータクリーニング
  - 構造化出力（JSON mode）への切り替え

## 3. データに関するリスク

### R-007 データセットの正解に誤りがある 🟡
- **影響度**: 中 / **発生可能性**: 中 / **スコア**: 4
- **予防策**:
  - 2人以上でのダブルチェック
  - 公的な出典を優先
- **発生時の対応**:
  - 発見次第、該当問題を除外または修正
  - 全問題の再チェック

### R-008 データのバックアップ消失 🔴
- **影響度**: 高 / **発生可能性**: 低 / **スコア**: 3
- **予防策**:
  - GitHub + Google Drive + ローカルの3重バックアップ
  - 週1回のバックアップ確認
- **発生時の対応**:
  - 3重バックアップから復旧
  - 最新版からの差分再構築

### R-009 公開データセットのライセンス違反 🟡
- **影響度**: 中 / **発生可能性**: 低 / **スコア**: 2
- **予防策**:
  - 使用前にライセンスを必ず確認
  - 商用利用の可否を確認
  - 改変配布の可否を確認
- **発生時の対応**:
  - 問題のあるデータを自作データに置き換え

## 4. スケジュール・進捗に関するリスク

### R-010 就活で研究が進まない 🔴
- **影響度**: 高 / **発生可能性**: 高 / **スコア**: 9
- **予防策**:
  - 週ごとに「研究日」を固定
  - 就活ピーク前（〜3月）に文献調査を完了
  - 就活状況を指導教員に共有
- **発生時の対応**:
  - 研究範囲を縮小（モデル数・問題数を減らす）
  - 執筆開始を11月に後ろ倒し
  - 最悪の場合、留年を含めた相談

### R-011 夏休みに進捗ゼロ 🔴
- **影響度**: 高 / **発生可能性**: 中 / **スコア**: 6
- **予防策**:
  - 8月初めまでにパイロット結果を出す
  - ゼミの同期と週1回の進捗共有
- **発生時の対応**:
  - 10月を集中実施月に
  - 執筆スケジュールを圧縮

### R-012 指導教員と連絡が取れない 🟡
- **影響度**: 中 / **発生可能性**: 低 / **スコア**: 2
- **予防策**:
  - 複数の連絡手段（メール・Slack・研究室訪問）
  - ゼミ時間に必ず顔を出す
- **発生時の対応**:
  - TAや他の教員に相談
  - 学科事務経由で連絡

## 5. 体調・生活に関するリスク

### R-013 体調不良で長期離脱 🟡
- **影響度**: 高 / **発生可能性**: 低 / **スコア**: 3
- **予防策**:
  - 定期的な健康管理
  - 無理な徹夜を避ける
  - 早期対応
- **発生時の対応**:
  - 指導教員に即座に報告
  - 研究範囲の縮小を相談
  - 休学も選択肢に

### R-014 メンタル面の不調（やる気の低下） 🟡
- **影響度**: 中 / **発生可能性**: 中 / **スコア**: 4
- **予防策**:
  - ゼミ仲間との定期的な交流
  - 小さな成功体験を積む（1日1タスク完了）
  - 完璧主義を避ける
- **発生時の対応**:
  - 学生相談室の利用
  - 信頼できる人に相談
  - 一時的な休息

## 6. 執筆・提出に関するリスク

### R-015 論文の初稿が12月末に完成しない 🔴
- **影響度**: 高 / **発生可能性**: 中 / **スコア**: 6
- **予防策**:
  - 11月から少しずつ書く
  - 方法・結果から先に書く
  - 1日500字の目標設定
- **発生時の対応**:
  - 年末年始に集中執筆
  - 章ごとに優先順位をつけて必須部分のみ先に完成
  - 考察の深さを必要最小限に

### R-016 提出直前のフォーマット不備 🟡
- **影響度**: 中 / **発生可能性**: 中 / **スコア**: 4
- **予防策**:
  - 4月中に提出要項を確認
  - テンプレートを最初から使う
  - 12月に一度フォーマットチェック
- **発生時の対応**:
  - 提出3日前の最終確認で発見・修正

### R-017 剽窃チェックに引っかかる 🟡
- **影響度**: 高 / **発生可能性**: 低 / **スコア**: 3
- **予防策**:
  - 引用ルールを正しく理解
  - 直接引用は最小限にし、必ず出典を明記
  - 間接引用も出典を明示
- **発生時の対応**:
  - 指摘箇所を自分の言葉で書き直す
  - 指導教員に即座に相談
