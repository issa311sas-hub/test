## 3. 予算超過時の対応フロー

### レベル1（月予算の 80% 超過）
- [ ] このドキュメントに原因メモ追加
- [ ] 来週の API 呼び出しを一時停止
- [ ] 原因分析（どの実験が想定より重かったか）

### レベル2（月予算の 100% 到達）
- [ ] API 呼び出しを即停止
- [ ] 翌月に持ち越すか検討
- [ ] リスク台帳 R-003 を発動、対応策を実施

### レベル3（月予算の 150% 超過）
- [ ] 指導教員に即報告
- [ ] 実験規模の縮小を検討
- [ ] 問題数を減らすか、モデル数を減らすか

## 4. コスト削減の工夫チェックリスト

- [ ] 実装前に小さいサブセット（5問）でコストを実測する
- [ ] 必要のないリトライを入れない
- [ ] プロンプト長を最適化する（冗長な指示を削る）
- [ ] バッチ API（OpenAI の Batch API, 50%オフ）を検討する
- [ ] キャッシュを効かせる（同じプロンプトは再利用）
- [ ] temperature=0 で sampling 回数を減らす
- [ ] ストリーミングは使わない（確定タスクには不要）
- [ ] 出力の最大トークン数を制限する（max_tokens=512 等）
- [ ] 予算上限に近づいたら run_pilot.py でエラー終了させる

## 7. メモ

- 予期せぬ高額請求の主な原因:
  - サンプリング回数の過剰
  - 長いプロンプト・長い出力
  - ループ時の例外でリトライが暴走
  - モデル指定のミス（安価モデルのつもりが高額モデル）
