# パイロット実験 Pre-Flight Checklist

> **目的**: 本物の API を叩く前にここを 1 回通す。数百〜数千円を無駄にしないための「離陸前チェック」
> **いつ使う**: `make pilot-openai` / `make pilot-anthropic` を初めて叩く直前
> **所要時間**: 10〜15 分

---

## 0. 哲学

- **疑わしい時は絶対に走らせない**
- **まずモック → 5 問 → 50 問 → 200 問** の順で段階的に拡大
- **1 回のミスが月予算の 50% を食うこともある**（プロンプト長さ×回数の掛け算）

---

## 1. コード・設定の検証（5 分）

### 1.1 テストが全部パスしているか
```bash
make test
```
- [ ] parser の 21 件テストが全てパス
- [ ] calibration の 14 件テストが全てパス
- [ ] 合計 35 件、失敗 0

> ❌ テストが 1 件でも落ちている状態で実行しない。データがムダになる。

### 1.2 モック実行で end-to-end が通るか
```bash
make mock
```
- [ ] `results/mock_run.csv` が生成される
- [ ] パース成功率 > 95%（50 問中 48 問以上）
- [ ] ECE / Brier / AUROC が計算される
- [ ] エラーメッセージが 1 行も出ない

### 1.3 サマリ生成が動くか
```bash
make summary
```
- [ ] `results/summary.md` が生成される
- [ ] 表が崩れていない

---

## 2. API キーと予算の確認（3 分）

### 2.1 `.env` ファイルの確認
- [ ] `.env` ファイルが存在する（`.env.example` ではなく）
- [ ] 該当する API キーが設定されている
- [ ] **キーが `sk-xxxxx` のままになっていない**（本物に差し替え済み）
- [ ] `.env` が `.gitignore` されていることを確認
  ```bash
  git check-ignore -v .env
  ```
  → `.gitignore:X:.env*` が返ればOK

### 2.2 API キーのスコープ・予算
- [ ] OpenAI: プロジェクトキーの月次上限を **3,000 円（$20 目安）** に設定済み
- [ ] Anthropic: Console で月次上限を設定済み
- [ ] キーがうっかり Organization 全体のキーになっていないか
- [ ] 使う予定のない API キー（Google など）はコメントアウト済み

### 2.3 モデル指定の確認
- [ ] 使用モデルは `prompts.py` または `run_pilot.py` で明示
- [ ] 安価モデル（-mini 系）と高価モデル（フル版）を **取り違えていない**
- [ ] モデル名の末尾に `-pro` や `-opus` が **誤って** 付いていない

## 3. 実行スケールの見積もり（3 分）

### 3.1 今回叩く問題数
- [ ] 問題数 = _____ 問
- [ ] プロンプト方式 = _____ 方式
- [ ] モデル数 = _____ モデル
- [ ] 繰り返し回数 = _____ 回
- [ ] **総 API 呼び出し回数 = 問題数 × 方式 × モデル × 繰り返し = _____ 回**

### 3.2 推定コスト（最悪ケース）
- [ ] 平均入力トークン ≈ _____ token / 呼び出し
- [ ] 平均出力トークン ≈ _____ token / 呼び出し
- [ ] モデル単価（入力） $ _____ / 1M tokens
- [ ] モデル単価（出力） $ _____ / 1M tokens
- [ ] **推定合計** $ _____ ≈ _____ 円

> **ルール**: 推定が月予算の 50% を超えたら、必ず問題数を減らす。

### 3.3 予算超過時の停止機構
- [ ] `run_pilot.py` に累計コスト監視が入っているか確認
- [ ] 入っていない場合: **最初は 5 問だけ叩いて実コストを実測する** ことを約束

## 4. データセットの確認（2 分）

### 4.1 入力 CSV の検証
- [ ] CSV のヘッダが期待通り（`id,domain,question,answer,choices`）
- [ ] 行数が想定通り
- [ ] 文字化けしていない（`head questions_sample.csv` で目視）

- [ ] 偏っていないか（例: 常識ばかり 40 問、歴史が 2 問、等は NG）

## 付録: よくあるミス集

| ミス | 発生時の損害 | 予防策 |
|---|---|---|
| sk-xxxxx のまま実行して 401 エラー | コストは 0 だが時間と気力を失う | 2.1 のキー確認 |
| `--questions full_dataset.csv` を誤って叩く | 想定の 4 倍のコスト | 3.1 の件数確認 |
| リトライループで同じ問題を何度も叩く | 2〜10 倍のコスト | リトライ上限を 3 に設定 |
| 高価モデルを指定していた（`-pro` 忘れていた） | 5〜20 倍のコスト | 2.3 のモデル名確認 |
| 出力トークン上限を設定していなかった | 2〜5 倍のコスト | `max_tokens=512` を明示 |
| temperature=1 で 5 回 sampling | 5 倍のコスト | temperature=0 or n=1 |
| プロンプトに余計な文脈（few-shot 100 例） | 10〜50 倍のコスト | プロンプト長を目視 |

---

> *「最悪のミスは、1 回の実行で 1 ヶ月分の予算を使うことではなく、
> それに気づかずに次の実験を走らせることだ。」*
