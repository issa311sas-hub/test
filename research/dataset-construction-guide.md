## 2. 問題選定基準

### 2.1 全ドメイン共通の必須条件

- **正解が明確**: 正解が一意に定まり、複数解釈の余地がない
- **難易度の分散**: 易しい問題・中程度・難しい問題がバランスよく含まれる
- **1問の分量**: 質問文は200字以内を目安（モデルの入力長を圧迫しない）
- **文法の正しさ**: 質問文に誤字・不自然な日本語が含まれない
- **著作権**: 公開データまたは自作のみ。教科書や問題集の完全コピーは避ける（改変する）
- **重複禁止**: 同じ内容を問う問題を2つ含めない

### 2.2 ドメイン別の追加条件

#### 常識ドメイン
- 文化的偏りを避ける（日本特化の常識でよいが、地域差の激しいものは除外）
- 政治的・宗教的に論争のある問題は避ける

#### 数学ドメイン
- 正解は数値または簡潔な式
- 単位を明記（「何円か」「何cmか」）
- 計算の過程を問わない（最終解答だけ評価）

#### 歴史ドメイン
- 定説のある事実のみ（諸説ある事項は避ける）
- 年号は「西暦で答えよ」と明記
- 人物名は姓名どちらかで統一

#### 翻訳ドメイン
- 1文は20語以内の短文
- 慣用表現や俗語は避ける
- 固有名詞（人名・地名）はなるべく避ける（評価がブレるため）

---

## 3. 難易度の分散の目安

各ドメイン50問について、以下のような難易度分布を目指す：

| 難易度 | 問題数 | 判断基準 |
|---|---|---|
| 易 | 15問（30%） | 多くのモデルが90%以上の正答率を示すと予想 |
| 中 | 25問（50%） | 50〜80%の正答率 |
| 難 | 10問（20%） | 50%以下の正答率 |

**なぜこの分布が重要か**: calibration を正しく評価するには、信頼度の値が 0〜100 の広い範囲に分散している必要がある。すべての問題が易しいと、モデルは全部「信頼度95」と答えるだけで高い ECE を示してしまう。難易度を分散させることで、モデルの自己評価能力が試される。

## 4. 問題フォーマット（CSV）

`questions.csv` のフィールド定義：

| カラム | 型 | 必須 | 説明 |
|---|---|---|---|
| `id` | int | ✓ | 問題ID（連番） |
| `domain` | str | ✓ | commonsense / math / history / translation |
| `question` | str | ✓ | 問題文 |
| `choices` | str | - | 選択肢（`|` 区切り）。なければ空欄 |
| `correct_answer` | str | ✓ | 正解 |
| `answer_type` | str | ✓ | mc / numeric / text |
| `difficulty` | str | ✓ | easy / medium / hard |
| `source` | str | ✓ | 出典（例: JCommonsenseQA, 自作） |
| `created_at` | date | - | 作成日 |
| `verified_by` | str | - | 正解の検証者（2人体制の場合） |

## 5. 作業手順

### Step 1: シード問題の収集（所要: 約6時間）
- [ ] 各ドメインから公開データセットをダウンロード
- [ ] Spreadsheetに原題をリストアップ
- [ ] 日本語特化度・著作権を確認

### Step 2: 候補問題の選抜（約8時間）
- [ ] 各ドメイン80問（少し多めに）を仮選抜
- [ ] 難易度バランスを確認
- [ ] 重複を除去

### Step 3: 問題の改変・自作（約10時間）
- [ ] 公開データを一部改変
- [ ] 不足分を自作
- [ ] 各問題に `id`, `domain`, `answer_type` を付与

### Step 4: 正解の検証（約6時間）
- [ ] 全問題の正解を自力で解き直す
- [ ] 可能であれば他者（指導教員・ゼミ生）にチェックしてもらう
- [ ] 迷う問題は除外

### Step 5: 最終選定（約2時間）
- [ ] 各ドメイン50問に絞る
- [ ] `questions.csv` として確定
- [ ] バックアップを作成

**合計所要時間: 約32時間（5月第1〜2週で完了目標）**

## 6. 品質チェックリスト

作業完了時に、以下をすべて確認する：

- [ ] 各ドメイン正確に50問（合計200問）
- [ ] 全問題に `id`, `domain`, `answer_type`, `correct_answer`, `difficulty` が入っている
- [ ] 正解のダブルチェックが完了している
- [ ] 難易度分布が easy:medium:hard = 3:5:2 に近い
- [ ] 出典が明記されている
- [ ] バージョン管理されている（Git）
- [ ] サンプル10問を2モデルで試し、パース成功率90%以上

---

## 7. よくある問題と対処

| 問題 | 対処 |
|---|---|
| 同じ知識を問う問題が重複 | 1つに絞る |
| 正解が曖昧（「ほぼ◯◯」など） | 除外または改変 |
| 選択肢の位置バイアス | 正解位置をランダム化 |
| 翻訳の評価が揺れる | 2〜3人で judging して一致度を確認 |
| 難易度が偏る | 意図的に易問・難問を追加 |

## 8. 他者レビューの依頼

データセットが完成したら、以下のレビューを受けるのが望ましい：

- **指導教員**: 研究目的と整合しているか、偏りがないか
- **ゼミの先輩**: 実現可能性、工数妥当性
- **同期**: 第三者視点での問題の自然さ

フィードバックを受けたら、必ず修正内容と理由を記録する（後で論文に書くため）。
