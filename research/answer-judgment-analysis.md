# 正答判定方法の選定分析

> **作成日**: 2026-06-18
> **目的**: 4ドメインそれぞれの正答判定方法を確立し、選定根拠を文書化する
> **ステータス**: 調査完了・判定方法確定

---

## 0. キャリブレーション研究における正答判定の重要性

キャリブレーション指標（ECE, Brier Score）はすべて **二値の正誤ラベル y_i ∈ {0, 1}** を前提とする。

```
ECE = Σ (|B_m|/n) × |acc(B_m) - conf(B_m)|
```

ここで `acc(B_m)` は y_i から直接計算される。つまり **y_i にノイズがあると ECE が直接汚染される**。

→ 正答判定の信頼性は、本研究の測定精度の上限を規定する最も重要な設計要素の一つ。

## 2. 各ドメインの判定方法（確定）

### 2-1. 数学（MGSM）: 正規化完全一致

**方法**: LLM 出力から数値を抽出し、正解の数値と比較する。

**正規化手順**:
1. LLM 出力から最終的な数値回答を正規表現で抽出
2. カンマ・通貨記号・単位を除去（例: "¥1,200" → "1200"）
3. 小数と整数の統一（例: "3.0" → "3"、ただし "3.14" はそのまま）
4. 抽出した数値と正解の数値を比較 → 一致なら y=1、不一致なら y=0

**根拠**: Calibration 研究における数学タスクの標準的な判定方法。ConfTuner (NeurIPS 2025) は GSM8K で同様の数値抽出・完全一致を使用。MGSM は GSM8K の翻訳であり、同一手法が適用可能。

**注意事項**:
- LLM が途中計算を含む長文を出力する場合、最後の数値を正解として採用する
- プロンプトで「最終的な回答を `回答: XX` の形式で出力してください」と指定し、抽出精度を担保する
- 回答が数値として抽出不可能な場合は y=0 とする

---

### 2-2. 常識（JCommonsenseQA）: 選択肢ラベル一致

**方法**: LLM 出力から選択されたラベル（0〜4）を抽出し、正解ラベルと比較する。

**正規化手順**:
1. プロンプトで「回答は選択肢の番号（0〜4）のみを出力してください」と指定
2. LLM 出力から番号を抽出（正規表現: `[0-4]`）
3. 正解ラベルと比較 → 一致なら y=1、不一致なら y=0

**根拠**: MC 形式の判定は calibration 研究で最も信頼性が高く、ノイズがゼロ。Xiong et al. (2024), "On Verbalized Confidence Scores for LLMs" (2024) 等、calibration 研究の 60-70% が MC 形式を採用する理由はここにある。

---

### 2-3. 知識（JMMLU）: 選択肢ラベル一致

**方法**: JCommonsenseQA と同一。選択肢ラベル（A/B/C/D）の一致で判定。

**正規化手順**:
1. プロンプトで「回答は A, B, C, D のいずれかのみを出力してください」と指定
2. LLM 出力からラベルを抽出
3. 正解ラベルと比較 → 一致なら y=1、不一致なら y=0

---

### 2-4. 翻訳（FLORES-200）: COMET スコア閾値 + LLM-as-a-Judge 検証

翻訳ドメインの正答判定は、本研究における方法論上の最大の論点である。以下に候補手法の比較分析と最終選定を示す。

#### 候補手法の比較

| 手法 | 人間評価との相関 | 二値化の容易さ | 再現性 | バイアス |
|---|---|---|---|---|
| BLEU | 低（システムレベル ~70.8%） | 閾値設定が必要 | ✅ 完全再現可能 | n-gram 重複のみ。意味的等価を見逃す |
| BERTScore | 中〜高 | 閾値設定が必要 | ✅ モデル指定で再現可能 | 日本語BERTモデル選択に依存 |
| **COMET** | **高（~83.9%）** | 閾値設定が必要 | ✅ モデル指定で再現可能 | 学習データに依存 |
| GEMBA-DA (GPT-4) | 最高（~89.8%） | 直接スコアリング可能 | △ API変更で変動 | LLM バイアス（後述） |
| **LLM-as-a-Judge** | **高（>80% 人間一致）** | 直接二値化可能 | △ API変更で変動 | 位置バイアス、冗長性バイアス等 |

#### BLEU を主判定に採用しない理由

Papineni et al. (2002) の BLEU は n-gram の表層一致に基づく。

- WMT22 でのシステムレベルペアワイズ精度は **70.8%** で、COMET (83.9%) や GPT-4 (89.8%) に大幅に劣る（Kocmi & Federmann, EAMT 2023）
- 日本語は語順の自由度が高く、同じ意味を異なる語順で表現できるため、n-gram 一致の限界が特に顕著
- 文レベル（セグメントレベル）の相関はさらに低い
- → **BLEU は補助参考値として報告するが、正答判定の根拠にはしない**

#### COMET を主判定指標に選定する理由

COMET (Rei et al., EMNLP 2020; 後続バージョン COMET-22, xCOMET) は、ソース文・翻訳文・参照訳を入力とするニューラル評価指標。

1. **人間評価との高い相関**: WMT22 でシステムレベルペアワイズ精度 83.9%。WMT23-24 のメトリクス共有タスクでも上位に位置する。xCOMET は WMT23 優勝指標。
2. **決定論的**: 同一モデル・同一入力に対して常に同一スコアを出力。LLM-as-a-Judge と異なり再現性が完全に保証される。
3. **日本語対応**: 多言語モデル（XLM-R ベース）で訓練されており、日本語を含む。WMT の日本語対評価でも使用実績あり。
4. **二値化戦略**: COMET スコアに閾値を設定して y ∈ {0,1} を生成する。閾値は人間アノテーションのサブセットで校正する。

**閾値設定の方法論**:
1. FLORES-200 の250文のうち50文（20%）を人間が二値判定（許容できる翻訳=1、許容できない翻訳=0）
2. 50文に対する COMET スコアの分布を確認
3. F1スコアを最大化する閾値を選定（一般的に COMET ≥ 0.80〜0.85 が "adequate" の境界とされる）
4. 選定した閾値を残り200文に適用

#### LLM-as-a-Judge を検証手段として併用する理由

LLM-as-a-Judge（Zheng et al., NeurIPS 2023 [6]）は人間評価との一致率が >80% であり、単独でも有力な判定手段である。しかし本研究では**主判定ではなく検証手段**として位置づける。

**主判定にしない理由**:

1. **バイアスの存在**: LLM 判定には以下の体系的バイアスが学術的に確認されている。

   | バイアス | 内容 | 定量的知見 | 出典 |
   |---|---|---|---|
   | 位置バイアス | ペアワイズ比較で位置に依存して判定が変わる | GPT-4 で ~65% の一貫性（35% で逆転） | Zheng et al. 2023 |
   | 冗長性バイアス | 長い回答を高く評価する傾向 | 全 LLM で +17.3% の長さバイアス | Saito et al. 2023 |
   | 自己強化バイアス | 自モデルの出力を高く評価 | GPT-4 で 10-25% の自己優遇 | NeurIPS 2024 |
   | 迎合バイアス | ユーザーの意見に合わせて判定を変える | 不正解への同調率 ~63.7% | ELEPHANT benchmark |

2. **再現性の問題**: API のバージョン更新やサーバー側の変更で結果が変動する可能性がある。卒論の再現性を考慮すると、決定論的な指標が望ましい。

3. **循環性の懸念**: 本研究では LLM の出力（翻訳）を評価する。その評価を別の LLM に委ねると、「LLM が LLM を評価する」循環が生じる。評価対象と同じモデルファミリーを判定に使うと自己強化バイアスが特に問題になる。

**検証手段としての使用方法**:
1. COMET 閾値で判定した y_i のうち、境界付近（閾値 ± 0.05）のサンプル50問を LLM-as-a-Judge で再評価
2. COMET 判定と LLM 判定の一致率を報告し、閾値の妥当性を検証
3. 一致率が低い場合は閾値を調整

**LLM-as-a-Judge のプロンプト設計（検証用）**:

```
以下の翻訳の品質を評価してください。

原文（日本語）: {source}
参照訳（英語）: {reference}
翻訳出力（英語）: {hypothesis}

この翻訳は原文の意味を正確に伝えていますか？
以下の基準で判定してください：
- 1（合格）: 原文の主要な意味が正確に伝わっている。軽微な表現の違いは許容。
- 0（不合格）: 意味の欠落、誤訳、または重大な文法エラーがある。

判定: [0 or 1]
理由: [1文で簡潔に]
```

**バイアス緩和策**:
- 参照訳を必ず提供する（reference-guided evaluation）
- 理由を先に述べさせてからスコアを出力（CoT 方式）
- 評価対象モデルと異なるモデルを判定者として使用

## 3. 判定方法のまとめ

| ドメイン | 主判定方法 | 判定基準 | ノイズ水準 | 補助・検証 |
|---|---|---|---|---|
| **数学** | 正規化完全一致 | 数値 == 正解 | ほぼゼロ | — |
| **常識** | 選択肢ラベル一致 | ラベル == 正解 | ゼロ | — |
| **知識** | 選択肢ラベル一致 | ラベル == 正解 | ゼロ | — |
| **翻訳** | COMET スコア閾値 | COMET ≥ θ（人間校正で θ を決定） | 低〜中 | LLM-as-a-Judge（境界サンプル検証）、BLEU（参考値） |

### 判定ノイズの ECE への影響

| 条件 | 判定ノイズ | ECE への影響 |
|---|---|---|
| MC（常識・知識） | 0% | なし |
| 数値一致（数学） | ~1-2%（抽出失敗等） | 無視可能 |
| COMET 閾値（翻訳） | ~5-10%（閾値付近） | 影響あり → 感度分析で対処 |

**翻訳ドメインの感度分析**: 閾値 θ を ±0.05 変動させて ECE がどの程度変わるかを報告する。これにより閾値選択の恣意性が結果に与える影響を透明化する。

## 4. 先行研究との対応

| 本研究の方法 | 先行研究での対応方法 | 整合性 |
|---|---|---|
| 数値完全一致 | ConfTuner 2025: GSM8K で完全一致 | ✅ 同一 |
| MC ラベル一致 | Xiong 2024: CommonsenseQA で MC 一致 | ✅ 同一 |
| MC ラベル一致 | "On Verbalized Confidence" 2024: MMLU で MC 一致 | ✅ 同一 |
| COMET 閾値 + LLM 検証 | 先行研究に翻訳ドメインの calibration 事例がほぼない | ✅ 新規性 |

**翻訳ドメインの判定方法は本研究の方法論的貢献の一つ** — 先行研究が翻訳を calibration 評価の対象にしてこなかったのは、まさに正答判定の困難さが理由と考えられる。COMET 閾値 + 人間校正 + LLM 検証の3段構えは、この問題に対する実用的な解決策を提示する。
