## 5.3 日本語特有の要因に関する考察

### 5.3.1 過信の原因仮説

1. **仮説A: 学習データ量の差**
   - 日本語データは英語の 1/100 程度（CommonCrawl 比率）
   - 知識の曖昧さを学習できていないため過信する可能性

2. **仮説B: 文化的な遠慮の学習不足**
   - 日本語の「自信なさげな表現」がデータに少ない
   - RLHF でのアノテータ文化の差

3. **仮説C: トークン粒度の影響**
   - 日本語はトークン効率が悪く、同じ文字数でもコンテキストが狭い
   - これが calibration を悪化させる可能性

### 5.3.2 ドメイン間の差の解釈

**数学ドメインの過信**:
- 計算ミスを「自分は分かっている」と誤認する傾向
- 部分的に正しい推論も最終答えが間違えば不正解扱いになる
- → モデル側の「誤りに気づけない」 failure mode

**常識ドメインの良好さ**:
- JCommonsenseQA 的な問題は訓練データに似たパターンが豊富
- 言い換えや分布シフトが少ない

**翻訳ドメインの特殊性**:
- 評価が rubric ベースで連続値
- 「流暢だが誤訳」のケースで過信が発生

### 5.3.3 モデル別の特徴

- **GPT-5**: 総じて safe side に寄る傾向、high-confidence lock-in が弱い
- **Claude**: 最も calibrated、ただし accuracy は GPT-5 より低い
- **Gemini**: ドメイン依存のばらつきが大きい
- **Swallow**: 日本語特化でも calibration は良くならない → 事前学習の工夫では不十分

## 5.4 実用的な示唆

### 5.4.1 日本語 LLM 利用者への提言

1. **重要判断では confidence < 0.8 を疑え**
   - 本研究の結果、0.8 付近は最も乖離が大きいゾーン
2. **プロンプトで「慎重に」と指示しても効果は限定的**
   - むしろ 0-100 整数で聞く方式の方が実効性が高い
3. **日本語特化モデルは calibration の観点では推奨しづらい**
   - 精度を優先する場合のみ選択

### 5.4.2 プロンプトエンジニアリングへの示唆

- 「自信度は慎重に見積もってください」というメタ指示の効果検証は今後の課題
- Chain-of-Thought（CoT）との組み合わせは今回未検証だが、過信を軽減する可能性

### 5.4.3 モデル開発への示唆

- 日本語特化の追加学習時に、calibration を明示的に損失に組み込む必要性
- RLHF フェーズでの「自信なさげな表現」のアノテーションを増やす

## 5.5 研究の限界

### 5.5.1 スケールの限界

- **問題数が各ドメイン50問**: 統計的検定の検出力が限定的
- **1モデルあたり 1回の実行**（または3回平均）: サンプリング分散が残る
- **4モデルのみ**: 結論の一般化には限界

### 5.5.2 方法論の限界

- **翻訳ドメインの主観評価**: rubric でもアノテータ間一致率が中程度
- **プロンプトテンプレートの数**: 4方式は限定的で、さらに多様な方式もあり得る
- **言語比較の対象が常識のみ**: 他ドメインでの日英差は未検証

### 5.5.3 時間的有効性

- LLM は頻繁にバージョンアップするため、本研究の結果は [2026年XX月] 時点の
  スナップショット。6か月後には異なる結果になる可能性がある。
- これを「限界」として明記し、リスク台帳の R-004 を引用する。

### 5.5.4 再現性

- API ベースの実験は temperature=0 でも完全な再現性は保証されない
- 商用モデルの内部アップデートを追跡できない
- → GitHub に生ログ（暗号化されたレスポンス）を保存して可能な限り再現性を担保

## 5.7 本章のまとめ

本章では、第4章の結果を先行研究と照らし合わせながら解釈した。主要なメッセージは
以下の3点である。

1. **日本語LLMの calibration は英語と比べて悪い傾向があり、その要因には学習データ量、
   RLHFの言語差、トークン粒度などが関わっている可能性がある。**
2. **プロンプト方式は calibration に影響するが、モデル間の差ほど大きくはない。
   モデル選定が calibration の最も重要な決定要因である。**
3. **実用上は、confidence の絶対値ではなく相対的な順位情報として使うのが安全で
   ある。特に 0.7〜0.9 の範囲は最も信頼できない。**
