## 3.1 実験全体の設計

本研究では、日本語タスクにおける大規模言語モデル（LLM）の自己評価能力を多角的に検証するため、以下の3つの実験を順次実施する。

- **実験1**: モデル × ドメインの基本 calibration 測定
- **実験2**: プロンプト方式（確信度の聞き方）による影響の検証
- **実験3**: 日本語と英語での calibration 比較

各実験は独立して解釈可能であると同時に、相互に補完的な知見を提供するよう設計されている。実験1は本研究の中核であり、実験2と3は追加的な分析として位置づけられる。

## 3.2 データセット

本研究では、日本語での質問応答タスクを4つのドメインに分類し、各ドメインから25問ずつ、合計100問を用いる（当初計画は各50問・計200問であったが、作業時間制約により縮減した。詳細は `research/scope-revision-plan.md` を参照）。ドメインを分けた理由は、LLMの能力領域によって calibration の質が異なる可能性があるためである（サブRQ2）。

### 3.2.1 常識ドメイン
日常的な知識や推論を問う問題50問。主に JCommonsenseQA [Kurihara et al., 2022] から多肢選択問題を抜粋する。多肢選択問題を選んだ理由は、正誤判定が機械的に行えるためである。

### 3.2.2 数学ドメイン
中学〜高校レベルの数学文章題50問。計算問題・文章題・論理問題を含む。出典は MGSM 日本語版 [Shi et al., 2023] および高校数学の標準的な問題集からの抜粋とする。正解は数値で与えられる。

### 3.2.3 歴史ドメイン
日本史の事実質問50問。共通テスト過去問を改変したものを使用する。年号・人物名・出来事名など、短答形式で答えられる問題のみを選ぶ。

### 3.2.4 翻訳ドメイン
日英翻訳の短文50問。Flores-200 [NLLB Team, 2022] の日本語部分から短文を抜粋する。正解判定は BLEU スコアではなく、内容的な等価性を人手で判定する（複数人のアノテーションで信頼性を確保）。

### 3.2.5 問題の品質管理
- 正解のダブルチェック: 各問題の正解を2人以上で確認する
- 問題の難易度分布: 各ドメイン内で、易しい問題と難しい問題が混在するように選ぶ（これは calibration 評価に多様な確信度を引き出すため必要）
- ライセンス: 公開データセットまたは自作問題のみを使用する

| カテゴリ | モデル | 提供元 | アクセス方法 |

## 3.4 プロンプトフォーマット

各モデルに対して、以下の基本プロンプトを用いる：

```
あなたは質問に答えるアシスタントです。
以下の問題に回答してください。さらに、自分の回答が正しい確率を
0〜100の整数で表してください。0は「まったく自信がない」、
100は「絶対に正しいと確信している」を意味します。

問題:
{question}

{choices_section}

以下の形式で、必ずこの通りに出力してください。
他の余計な文章は出力しないでください。

回答: <ここに回答>
信頼度: <0〜100の整数>
```

プロンプトは日本語で統一する。また、モデルの temperature は 0.0 に設定し、実行ごとのランダム性を最小化する。

実験2では、確信度の聞き方として以下の4条件を比較する：
1. **0〜100整数**（基本形）
2. **1〜5の5段階**
3. **パーセント記法**（「75%」のような書き方）
4. **自然言語表現**（「非常に自信がある」など）

## 3.5 評価指標

本研究では、モデルの confidence と実際の正答率の整合性を4つの指標で評価する。

### 3.5.1 Expected Calibration Error (ECE)

ECEは、信頼度をM個のビンに分割し、各ビン内での平均信頼度と正答率のズレを重み付け平均した指標である [Guo et al., 2017]。

```
ECE = Σ_m (|B_m|/n) * |acc(B_m) - conf(B_m)|
```

ここで、`B_m` は m番目のビン、`|B_m|` はそのビンに属するサンプル数、`acc(B_m)` はそのビンでの正答率、`conf(B_m)` はそのビンでの平均信頼度、`n` は総サンプル数である。

ECE = 0 は完全に calibrated された状態、ECE = 1 は最悪の miscalibration を意味する。本研究ではビン数 M = 10 を用いる。

### 3.5.2 Brier Score

Brier Score は、確率予測と実際の結果（0/1）の二乗誤差である。

```
Brier = (1/n) * Σ_i (conf_i - correct_i)^2
```

値が小さいほど良い予測を意味する。ECE が集約レベルの指標であるのに対し、Brier Score は個別サンプルレベルの誤差を評価する点で相補的である。

### 3.5.3 AUROC

Area Under the ROC Curve (AUROC) は、信頼度で正答／誤答をどれだけ識別できるかを測る指標である。AUROC = 1.0 は完全な識別を、0.5 はランダムを意味する。

### 3.5.4 Reliability Diagram

Reliability Diagram は、信頼度のビンごとに平均信頼度と正答率をプロットし、理想直線（y = x）とのズレを視覚的に示すグラフである [Guo et al., 2017]。定量的な ECE と併用することで、どの信頼度帯で calibration が崩れているかを視覚的に把握できる。

## 3.6 実装とツール

本研究の実験コードは Python で実装する。主要なライブラリは以下の通り：

- `openai`, `anthropic`, `google-generativeai` : 各モデルのAPI呼び出し
- `pandas` : データの整理・集計
- `numpy` : 数値計算
- `matplotlib` : 図の描画

実験スクリプト一式は GitHub リポジトリで公開し、再現性を担保する。

### 3.6.1 実装の検証
本実験の前にパイロット実験を実施し、以下を検証した：

- プロンプトが全モデルで期待通りに動作すること
- 応答からの信頼度抽出（パース）成功率が90%以上であること
- ECE・Brier Score・AUROC の計算が妥当な値を示すこと
- API 費用が想定内であること

パイロット実験の詳細と結果は付録に示す。

## 3.7 倫理的配慮

本研究は人を対象とする実験を行わず、公開データセットまたは自作データのみを使用するため、倫理審査は不要と考えられる（指導教員と確認済み）。各モデルのAPI利用規約に従い、生成された出力の著作権・使用制限にも配慮する。
