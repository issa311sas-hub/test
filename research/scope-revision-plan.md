## 2. 実験スコープの段階別縮小案

**原則**: 最初はフルスコープで設計しておき、時間不足が判明した時点で段階的に縮小する。

### レベル 0: フルスコープ（現在の計画）
- **モデル**: 4（GPT-5 / Claude / Gemini / Swallow）
- **ドメイン**: 4（常識 / 数学 / 歴史 / 翻訳）
- **プロンプト方式**: 4（0-100 整数 / 5 段階 / % / 自然言語）
- **問題数**: 200 問
- **総 API 呼び出し**: 200 × 4 × 4 = **3,200 回**
- **想定コスト**: 10,000〜15,000 円
- **想定本人作業**: 84h（AI 支援前提）

### レベル 1: 軽量スコープ（時間不足の初期対応）
- **モデル**: 3（GPT-5 / Claude / Swallow）
- **ドメイン**: 4（変更なし）
- **プロンプト方式**: 3（0-100 整数 / 5 段階 / 自然言語）
- **問題数**: 150 問
- **総 API 呼び出し**: 150 × 3 × 3 = **1,350 回**
- **想定コスト**: 5,000〜8,000 円
- **想定本人作業**: 60h
- **発動条件**: 7 月末時点で本人進捗が 50% 未満

### レベル 2: 最小スコープ（緊急削減）
- **モデル**: 2（GPT-5 / Claude）
- **ドメイン**: 2（常識 / 数学）
- **プロンプト方式**: 2（0-100 整数 / 自然言語）
- **問題数**: 100 問
- **総 API 呼び出し**: 100 × 2 × 2 = **400 回**
- **想定コスト**: 2,000〜3,000 円
- **想定本人作業**: 40h
- **発動条件**: 9 月末時点で本人進捗が 40% 未満
- **論文への影響**: 比較研究としての主張は弱まるが、単一モデルの deep dive として十分成立

### レベル 3: 論文成立の最低ライン
- **モデル**: 1（Claude のみ）
- **ドメイン**: 2（常識 / 数学）
- **プロンプト方式**: 1（0-100 整数）
- **問題数**: 50 問
- **総 API 呼び出し**: 50 回
- **想定コスト**: 500 円以下
- **想定本人作業**: 25h
- **発動条件**: 11 月末時点で本人進捗が 30% 未満
- **論文への影響**: 単一モデル・単一プロンプトの事例研究。比較研究ではなくなるが、
  DEL フレーミング（`advisor-theme-alignment.md` 参照）で理論的意義を前面に出せば成立

## 3. AI 活用の具体的な分担

### 3.1 AI（Claude）が担当する工程
- [x] 先行研究の要約カード作成（8 本分）
- [x] データセット 100 問の初期生成（ドメイン別）
- [x] 実験コードの記述・保守・バグ修正
- [x] 結果の統計処理と可視化コード
- [x] 論文各章の初稿執筆
- [x] 参考文献 BibTeX 管理
- [x] 面談準備資料の作成
- [x] 週次・月次レビューのテンプレート埋め
- [x] DEL × LLM の理論的フレーミング提案

### 3.2 本人が担当する工程（AI に任せられない）
- [ ] **意思決定**: テーマ確定、モデル選定、最終スコープ
- [ ] **品質検証**: データセットの正解確認、AI 生成論文の事実確認
- [ ] **考察と結論**: 結果の意味付け、限界の認識、将来展望
- [ ] **指導教員面談**: 対話・方向確認・承認取得
- [ ] **説明責任**: 審査で質問されたら自分の言葉で答えられる状態
- [ ] **倫理的判断**: 何を書き、何を書かないかの最終判断

### 3.3 グレーゾーン（両者協働）
- 先行研究の精読 → Claude 要約＋本人が核心部分を読む
- 実験結果の解釈 → Claude 初期解釈＋本人が妥当性確認
- 論文推敲 → Claude 文章改善＋本人が一貫性確認

## 4. 時間配分の月別スケジュール（改訂版）

| 月 | 本人作業 | 主な内容 | AI 支援 |
|---|---|---|---|
| 4 月 | 8h | テーマ確定、研究計画書承認、自己分析 | 計画書草稿・面談準備 |
| 5 月 | 8h | 先行研究精読（Week 1〜2）、データセット設計 | 文献要約・データ雛形生成 |
| 6 月 | 10h | データセット 100 問の品質確認、パイロット実行、**中間発表資料の着手** | 問題生成・コード保守・スライド雛形 |
| 7 月 | **12h** | **中間発表概要 2p 提出（7/17 正午厳守）、発表（7/20-27）**、本実験設計 | 概要草稿・スライド草稿・リハ補助 |
| 8 月 | 10h | 本実験実行、データ収集 | スクリプト自動実行 |
| 9 月 | 10h | データ分析、第 4 章結果草稿 | 可視化・統計処理 |
| 10 月 | 8h | 第 3 章方法、第 4 章結果の確認 | 章草稿 |
| 11 月 | 10h | 第 2 章関連研究、第 5 章考察、第 1 章序論の推敲 | 章草稿 |
| 12 月 | 8h | 全章統合、第 6 章結論、参考文献整理 | 最終稿生成 |
| 1 月 | 2h | フォーマット最終確認、提出 | チェックリスト確認 |
| **合計** | **86h** | | |

> **注**: 原計画は 84h だったが、中間発表（卒業研究1）が判明したため 7 月を +2h して 86h に修正。
> 週 2h × 42 週 = 84h 予算に対し 2h 超過するため、7 月は特別に週末集中日を 1 日加えるか、
> 他月から 2h を前借りする。

| 7 月 | **中間発表概要 7/17 提出・発表 7/20-27 完遂**、パイロット分析完了、本実験設計 | 再発表 8/5 に回避、本実験設計は 8 月へスライド |

### 5.2 アラート条件
- **黄色アラート**: 2 ヶ月連続で進捗 80% 未満 → 次月の作業を軽量化
- **赤アラート**: 3 ヶ月連続で進捗 60% 未満 → 次レベルスコープへ縮小
- **緊急**: 作業時間が月 4 時間を下回る → 教員に即報告し戦略相談

## 6. この計画の前提と脆弱性

### 6.0 確定済み情報（2026-04-10〜04-13 本人確認）
- **提出期限**: 1 月中（具体日は未定）
- **中間発表（卒業研究1）**（2026-04-13 詳細判明）:
  - 概要（2 ページ PDF）提出: **2026-07-17（金）12:00 厳守** / LETUS
  - 発表会: **2026-07-20（月）〜 07-27（月）** 期間内のグループ別日時
  - 発表形式: PowerPoint 6 分 + 質疑 3 分 = 9 分
  - 不十分な場合の再発表: **2026-08-05（水）**
  - 出席教員: 各グループ 2 名
  - 日程調整の締切: 2026-07-16（木）正午（教務幹事へ連絡）
- **執筆ツール**: LaTeX
- **Python 環境**: pip / Anaconda 利用可能（環境構築済み）
- **API キー**: 本人立替精算

### 6.0.1 中間発表（卒業研究1）のゲート条件

7 月 17 日の概要提出から逆算したマイルストーン:
- **6 月末**: パイロット結果が出揃っている（スライドに数値を載せられる）
- **7 月第 1 週**: スライドドラフト v1・概要ドラフト v1 完成
- **7 月第 2 週**: 教員フィードバック（時間が取れれば）＋リハ 1 回
- **7 月 17 日 正午**: 概要 PDF を LETUS 提出（**絶対死守**）
- **7 月 20〜27 日**: 発表（具体日はグループ割当待ち）
- **万一の保険**: 8 月 5 日再発表

### 6.1 前提
1. Claude が安定して使える（モデル変更や API 値上げがない）
2. 本人が Claude の出力を「読んで意味を理解できる」
3. Claude の生成物に重大な誤りが紛れ込まない
4. 教員が AI 活用を許容する（2026 年時点で一般的な認識と仮定）

### 6.2 脆弱性
- **Claude の停止・劣化**: 代替として GPT-5 / Gemini を準備
- **本人の理解不足**: 説明責任ルール（R-020）を定期チェック
- **誤情報の混入**: 重要事実は必ず一次資料で確認する習慣
- **教員の AI 忌避**: 事前にポリシーを確認、必要なら「どの作業を AI でやったか」を透明化

### 6.3 救済措置
- 週 2 時間が確保できない週が連続したら、その旨を daily-log に記録
- 月次レビューで累積遅延を可視化
- 最悪ケースでもレベル 3 スコープで論文は成立するようにしておく

---

## 7. 結論

**この計画は実行可能だが、ギリギリである。**

- AI 活用前提なら 84 時間で十分に論文は完成させられる
- ただし毎週 2 時間は絶対死守する必要がある
- 月次で進捗を確認し、未達があれば即スコープ縮小
- 最悪ケースでもレベル 3 スコープ（単一モデル・50 問）で論文は成立する
- DEL フレーミング（`advisor-theme-alignment.md`）を使えば、実験が小さくても
  理論的意義で補強できる
