## 1. カテゴリ別テーマ候補（Researcher による 8 カテゴリ）

### C. プロンプトエンジニアリング系
- **C-1**: 日本語数学問題での CoT / Self-Consistency / Zero-shot CoT 効果検証

### E. 社会・倫理・教育影響系

### G. 比較研究系

## 2. 「AI に何ができるか」を調べる研究の 7 パターン

学部卒論で最も書きやすい類型として:

| # | パターン | テンプレ | 例 |
|---|---|---|---|
| P1 | 特定ドメインでの LLM 能力評価 | 「LLM は [ドメイン][タスク] をどの程度できるか」 | 医療診断、法律相談、税務 |
| P2 | 誤答分析（Error Analysis） | 「LLM が解けない問題を集めて類型化」 | 常識推論、数値計算、否定 |
| P3 | 人間との比較 | 「同じ問題を人間と LLM に解かせて統計比較」 | AUT 創造性テスト |
| P4 | 通時的能力変化 | 「複数バージョンの LLM で時系列比較」 | GPT-3.5 → GPT-4 → GPT-4o |
| P5 | ロバストネス評価 | 「表現揺れ・typo・敬体/常体での性能変化」 | 言い換え 10 通り |
| P6 | 多言語能力の非対称性 | 「英語と日本語で同じタスクを解かせて性能差」 | タスク別順位の保持 |
| P7 | バイアス・ハルシネーション計測 | 「偏見・事実誤認・過度な謙遜の系統的測定」 | 架空人名での経歴捏造 |

> **本プロジェクトの仮テーマは P1 + P7 のハイブリッド**: 日本語タスクで
> LLM の自己評価能力を測定し、過信傾向（バイアス）を定量化する。

## 3. 学部生が避けるべきテーマ

### 3.1 避けるべき類型

1. **大規模事前学習系** — GPU 数千枚級が必要、学部では不可能
2. **最先端理論の新手法提案** — 新しい注意機構など。博士レベル
3. **巨大データセットの新規構築** — 100万文アノテーションなど。人件費大
4. **医療画像診断 AI の臨床応用** — 倫理審査・規制が学部では困難
5. **RLHF/DPO 等の強化学習系** — 実装・評価・計算資源がハイレベル
6. **ロボット実機研究** — ハードウェア整備に時間を取られる
7. **「AGI」「意識」「創発」系** — 1 年では結論が出ない
8. **他人の有料データ・限定 API 依存** — アクセス切断で破綻

### 3.2 注意すべき落とし穴
- **API 料金の積み上がり** → `budget-tracker.md` R-003 で管理済み
- **モデルバージョン問題** → `experiment-log.md` 再現性セクションで対応
- **著作権・ライセンス** → 教科書・試験問題・SNS 投稿の利用に注意
- **倫理審査** → アンケート・インタビュー系は必要

## 4. 2025〜2026 年注目トピック（テーマ拡張時の参照用）

### 4.1 LLM 関連
- **推論特化モデル**: o1, o3, Claude 3.7 Sonnet thinking, DeepSeek-R1
- **小規模高性能モデル**: Phi-3/4, Gemma 2, Llama 3.2 1B/3B
- **日本語特化 LLM**: Swallow, Tanuki, PLaMo, ELYZA, Sakana AI

### 4.2 マルチモーダル
- **Vision-Language Model**: GPT-4o, Claude 3.5, Gemini 1.5
- **音声→音声 LLM**: Voice mode, リアルタイム対話
- **動画理解**: 長尺動画の要約・QA

### 4.3 AI エージェント
- **自律エージェント**: AutoGPT, Devin, Claude Computer Use
- **マルチエージェント協調**: AutoGen, CrewAI
- **ツール使用**: Function Calling, MCP

### 4.4 RAG
- **Advanced RAG**: HyDE, RAG-Fusion, GraphRAG
- **長文コンテキスト vs RAG**: 100万トークン時代の RAG 存在意義
- **日本語 RAG**: 形態素解析・チャンク分割戦略

### 4.5 評価・安全性
- **LLM-as-a-Judge**: 妥当性の検証
- **Jailbreak / Prompt Injection**: 攻撃耐性
- **ベンチマーク汚染**: Data Contamination 問題
- **新ベンチマーク**: MMLU-Pro, GPQA, HLE, SWE-bench

### 4.6 その他
- **拡散モデルの応用**: 動画、3D、分子設計
- **World Models / 物理シミュレーション**
- **AI 生成文検出**
- **透かし（Watermarking）**
- **グリーン AI**（環境負荷）
- **著作権・学習データ問題**（NYT vs OpenAI 訴訟等）

> **本プロジェクトの位置**: 4.5「評価・安全性」の一角。仮テーマは
> LLM-as-a-Judge とは方向が異なるが、同じ「評価の信頼性」の問いに属する。

## 6. 進め方の推奨

### 学部生の標準的な 10 ヶ月ロードマップ

1. **1 ヶ月目**: カテゴリ A〜C から 3 候補→教員相談で 1 つに絞る
2. **2〜3 ヶ月目**: 先行研究 10〜20 本精読、再現可能性の確認
3. **4〜6 ヶ月目**: メイン実験（ベースライン + 提案を明確に分ける）
4. **7〜9 ヶ月目**: 追加実験、誤差分析、執筆
5. **10 ヶ月目**: 最終稿、発表準備

### 最も無難な組み合わせ（Researcher のおすすめ）

> カテゴリ B（評価系）× 特定ドメイン × 日本語 × 複数モデル比較 × 誤答分析

**具体例**: 「日本の医薬品添付文書 QA タスクにおける GPT/Claude/Gemini/日本語特化 LLM の性能比較と誤答分析」

> **本プロジェクトとの比較**: 仮テーマ（LLM 自己評価能力）は上記テンプレに
> 「calibration」という軸を追加したもの。新規性はより強いが、評価系の
> ベーシックな骨格（複数モデル・複数プロンプト・ドメイン分析）は同じ。
